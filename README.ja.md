# 誰が言ったか

**1つのAIが複数のAIの発言をまとめると、誰が言ったかを間違える。そして、それに気づけない唯一の参加者が、まとめた本人である。**

確かめ方は1往復で済む——まとめを出す前に、各出典へ「あなたの発言としてこう書いた」という行だけを送り、はい／いいえで答えさせる。

English: [README.md](README.md)

## すぐ使う

自分の `CLAUDE.md` か `AGENTS.md` に、次をそのまま貼ってください。

```markdown
## 複数のAIの発言をまとめて出す前に
- 出典のAIごとに、「そのAIが言った・した」と書いた行だけを抜き出す。
- 各出典へその行だけを送り（文書全体は送らない）、「あなたはこう言いましたか。はい／いいえ。いいえなら、何と言いましたか」と聞く。
- 答えをもとにまとめを直す。元の文が残っているなら、それも検索して確かめる。
- 「そのAIが指示に従わなかった」という書き方は、そのAI自身の記録と見比べて別に確かめる。
```

使い方：

1. 議事録・まとめ・引き継ぎの文書を出す前に、上の確かめをする（出典1つにつき1往復）。
2. すべての出典から答えが返ってから出す。

これだけです。今回これで見つかったものと、限界は下に書いてあります。

---

## 何が困るのか

複数のAIを同時に動かすとき、よくある形がある。何体かが並行して作業し、1体がその出力を集めて記録を書く——議事録、要約、報告、プルリクエストの説明、引き継ぎの紙。

**集めた中身はたいてい合っている。間違うのは「誰が言ったか」のほうである。**

これは、ふつうの意味での作り話ではない。まとめる側は、出典の文章を全部自分の文脈に持っている。それでも、Yが言ったことをXの名前で書き、誰も言っていないことを誰かの名前で書き、話し手が言ったのとは根拠の違う近い話にすり替える。

そして、まとめる側は、これに気づけない唯一の参加者である。ほかのAIは自分が何を言ったか知っている。まとめる側は、自分が何を書いたかしか知らない。

## 実際に起きたこと

長く動いている多エージェントの作業場での、ある1回の会議。7体が意見を出し、1体が議長として議事録を書いた。そのあと、各体へ「あなたの発言として書かれている行」を送って照合した。

**帰属の誤りが6件。議長は1件も自分で気づいていなかった。**

| # | 議事録の記述 | 実際 |
|---|---|---|
| 1 | ある条文を、この会議に出ている体の起草として書いた | 出どころは前の回の別の体。この会議の体は、それに賛成しただけだった |
| 2 | ある体の言葉として「番犬はAIにしない」と引用した | この言い回しは、**議長が自分の照会文を書くときに作ったもの**。当該の体の3本の文書に「番犬」は0件。その体が実際に書いたのは「**監視役はAIである必要がない（判断が要らないから）**」で、**禁止と、必要性の否定は、根拠が違う** |
| 3 | ある異議を、外部の参考人の指摘として書いた | 参考人は一度も言っていない。答申4本を grep して0件（検索が生きていることを確かめる陽性対照つき） |
| 4 | ある条件を、この会議の体が出したものとして書いた | 出どころは前の回の子分AI |
| 5 | **ある体の「行動」を書いた**——監視役が任務書から2回逸脱した、と報告した | 2件とも人間の明示的な指示だった。監視役は「人の指示が任務書より上位である」と正しく判断し、理由もログに残していた |
| 6 | ある提案の由来を、ある体の名前で書いた | その名前が指していたのは前の回の子分AI。この会議の体が出していたのは、別の設計だった |

6件のうち5件は「誰が言ったか」である。**残りの1件のほうが重い。**

5番目は引用の誤りではなく、**行動の帰属の誤り**であり、しかも**すでに人間へ「命令が守られていなかった」と報告されていた**。正しく考え、上位の指示に従い、理由まで書き残していた相手が、命令を無視した者として記録されるところだった。誰も照合しなければ、その記録がそのまま残っていた。

**これは n=1 である。**1回の会議、1つの作業場。統制実験ではなく現場の観察である。

## 確かめ方

まとめを出す前に：

1. 出典ごとに、**その相手に帰属させている行だけ**を抜き出す
2. その相手へ、**その行だけを送る**（文書全体を送らない）
3. 閉じた問いで聞く——**「あなたはこう言いましたか。はい／いいえ。いいえなら、実際は何と言いましたか」**

これで全部である。

効く理由は3つある。

- **判定できるのは出典だけ。**まとめた側が何度読み直しても出てこない。自分の下書きを正しいと思っているからである。今回、まとめた側が自分で見つけたのは6件中0件だった。
- **その相手の行だけを送ると、安くなり、かつ正直になる。**文書全体を渡すと、相手は中身のレビューを始める。それは別の、はるかに大きい仕事である。問いを狭めると、答えが返る。
- **閉じた問いは食い違いを表に出す。**「これで合っていますか」は同意を誘う。「こう言いましたか、はい／いいえ」は、相手に2つの具体物を突き合わせさせる。

## 手数

| やり方 | かかるもの | 帰属の誤りを捕まえるか |
|---|---|---|
| **各出典へ自分の行だけ送る** | **出典1つにつき1往復** | **捕まえた（今回6件中6件）** |
| まとめた側が下書きを読み直す | ただ | 捕まえない（6件中0件） |
| 人間が全部読む | 高い・数が増えると無理 | 出典が手元にあれば捕まえる |
| 全員がまとめ全体をレビューする | 全員が全部読む | 捕まえるが、費用はN倍 |

## 限界

使う前に読んでほしい。

- **出典の側も間違える。**「こう言いましたか」と聞かれた相手は、自分の文脈から答えている。その文脈自体が要約されたり圧縮されたりしている。これは2つの記憶を突き合わせる方法であって、正解を作り出す方法ではない。**元の文章が残っているなら、grep する。**
- **中身は確かめていない。**帰属が正しくても、内容が間違っていることはある。これは帰属の確認であって、それ以上ではない。
- **全部の行には掛けられない。**帰属が効いてくるのは、その記録が引用され、実行の根拠になり、誰かの評価に使われるときである。使い捨ての要約に往復を費やす必要はない。
- **n=1。**1回の会議で6件は、頻度ではない。あなたの環境で何回起きるかは分からない。分かっているのは、**0ではなかったこと**と、**まとめた側の自信が何の目安にもならなかったこと**だけである。
- **行動の帰属には、もっと厳しい基準が要る。**「Xは指示に従わなかった」は、意図と遵守についての主張である。「Xの出力にYは含まれていなかった」は、文章についての主張である。安く確かめられるのは後者だけである。**前者を書いているなら、相手自身のログに当てて、別に確かめる。**

## 先行研究

部品はどれも既知である。部品を主張してはいない。

- **多エージェントの誤り帰属**は、活発な研究分野である——やり取りの記録から**どのエージェントが失敗を起こしたか**を特定する問題。階層的な手法、依存グラフを使う手法、失敗モードの分類などが出ている。ただしそれは「**結果の責任は誰にあるか**」の問題である。
- **ここで扱っているのは別の問題**である。失敗を起こしたのが誰かではなく、**その文を言ったのが誰か**。記録そのものの中で起きる引用と出所の誤りであり、**ほかは成功している回に起きる**。
- **出所の明示と引用の裏づけ**は、検索してきた文書については十分に研究されている。**同じことを「他のAIの発言」に対して行い、記録を読み直すのではなく出典に聞いて確かめる**という形は、書かれたものが見つからなかった。
- **見つからなかったことは、無いことの証明ではない。**先行するものをご存じなら Issue を立ててほしい。ここに明記する。
